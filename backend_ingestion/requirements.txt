# ⚠️ setuptools MUST be pinned <81: passlib 1.7.4 unconditionally does `import pkg_resources` at `passlib/pwd.py:16`,
# while **setuptools>=81 has removed the pkg_resources module** (official wording: *"The pkg_resources package is
# slated for removal as early as 2025-11-30. Refrain from using this package or pin to
# Setuptools<81."*). Chain of failure: `import fastapi_users` → `fastapi_users/password.py:3
# from passlib import pwd` → `passlib/pwd.py:16 import pkg_resources` →
# ModuleNotFoundError → uvicorn cannot start.
# Local verification (Python 3.13.16 clean venv): under setuptools 84.0.0 the chain always crashes; under 80.9.0 (<81)
# `import pkg_resources` works (only a DeprecationWarning), and `import fastapi_users` returns 12.1.3.
# Note: although the python:3.11-slim image ships setuptools, a rebuild will pull the latest version, so it must be
# pinned here. The long-term fix is to remove passlib (upgrade fastapi-users>=13 to use pwdlib); see orders/20-dispatch.md T4.
setuptools<81
# ⚠️ bcrypt MUST be pinned to 4.x: passlib 1.7.4 (fastapi-users' password-hash backend) reads
# `bcrypt.__about__.__version__` to probe the backend, but **bcrypt 5.0.0 removed `__about__`**,
# so passlib falls back to the `detect_wrap_bug()` probe, which calls hashpw with a 72+ byte password,
# and bcrypt 5.x instead raises ValueError directly → register/login all return 500.
# Local verification: under bcrypt 5.0.0, POST /auth/register returns 500 (ValueError: password
# cannot be longer than 72 bytes); after downgrading to 4.0.1 it returns 201. See the PR's "verification" section.

# R-07 — 端到端联调与压测规格

> 对应订单 06（收口单）。派工正文见 `orders/06-dispatch.md`。
> 本文件规定**判据本身**：什么叫"就绪"、什么叫"通过"、什么叫"未验证"。

## 1. 启动顺序与就绪判据

| # | 组件 | 就绪判据（真实探测，禁止裸 sleep） | 超时 |
|---|---|---|---|
| 1 | TimescaleDB | `pg_isready -U postgres -d robot_monitor` 返回 0 | 60s |
| 2 | Redis | `redis-cli ping` 返回 `PONG` | 30s |
| 3 | EMQX | 1883 端口可连 **且** `docker compose ps` 健康态 | 90s |
| 4 | 后端 | `GET /healthz` 返回 **HTTP 200** | 60s |
| 5 | 告警引擎 | 进程存活 + 日志无启动异常 | 30s |

**EMQX 单独强调**：它的启动明显慢于 DB/Redis。若只等 DB 就开跑模拟器，
MQTT 连不上 → 写入 0 条 → 会被误判为"代码有 bug"，实为环境未就绪。

## 2. 数据链路真值校验

必须用**真实 SQL 计数**，不得用"容器日志无报错"代替：

```sql
SELECT count(*) FROM robot_metadata;    -- 期望 = 100
SELECT count(*) FROM robot_telemetry;   -- 30s × 100 台 × 10Hz ≈ 30000
SELECT rule_id, count(*) FROM robot_alert GROUP BY rule_id;
```

- `robot_telemetry` 阈值允许 **±10%**（模拟器启动/停止有边界损耗），必须给出实际值
- 告警至少命中两类：`motor_temp`、`battery_low`

## 3. 压测指标（区分实测 / 推测）

| 指标 | 采集方式 | 目标 |
|---|---|---|
| 端到端吞吐 | 模拟器上报计数 / 运行时长 | ≥ 1000 msg/s |
| 落库批耗时 | `BatchWriter` 打点，取 P50/P95 | P95 < 200ms |
| 队列积压峰值 | `/healthz` 的 `queue_depth` | 不持续增长 |
| MQTT 丢弃数 | `/healthz` 的 `mqtt_dropped` | 0（有值要说明原因） |
| 前端刷新频率 | store 每秒更新次数 | ≈10 次/秒（证明 100ms 节流） |

**前端节流验证方法**：
100 台 × 10Hz = 1000 msg/s 进入浏览器。若未节流，React 每秒收到 1000 次通知，
主线程打满、页面卡死。节流后每秒仅 10 次 —— 用计数器实测该值即可判定。

## 4. 报告结构（强制 7 分栏）

1. 基础设施状态
2. 后端
3. 前端
4. 压测
5. telemetry 行数
6. alert 行数
7. 结论

**并且**：

- 「环境错误」与「代码错误」**两栏分开**，禁止混列
- 每个"通过"附**实际命令 + 输出摘要**
- 未通过项标 **「未验证」** 并写明所需条件

### 环境错误 vs 代码错误 的判定准则

| 判为环境错误 | 判为代码错误 |
|---|---|
| 镜像拉取被墙 / 超时 | SQL 语法错误 |
| 端口被占用 | 字段名前后端不一致 |
| 依赖安装失败（如 PyPI 403） | 类型不匹配（字符串 vs 数字） |
| Docker Desktop 未运行 | 逻辑缺陷（阈值/去重/节流失效） |

## 5. 已知环境限制（主代理实测，2026-10-10）

以下属**环境错误**，不得归因于代码：

- **PyPI 在本机被拦截**：`403 Client Error: Forbidden for url: https://files.pythonhosted.org/...`
- **`asyncpg==0.29.0` 在 Python 3.13 无法编译**（`_PyLong_AsByteArray` 签名变更）
  → 部署镜像已锁定 `python:3.11-slim`（有预编译 wheel），本机 3.13 才装不上
- 因此**后端/告警引擎的运行时验证在本机无法完成**，只能在 Docker 内做

## 6. 禁止项

1. 禁止用"日志无报错"代替通过判定
2. 禁止为通过而放宽阈值（30000 → 300）
3. 禁止把环境错误写成代码错误（反之亦然）
4. 禁止整单判失败 —— 未实现模块标「跳过（阶段 X 未完成）」
5. 禁止伪造实测数字

## 7. 收尾要求

- 脚本必须 `trap` 清理（停后端/告警进程）
- 提供 `--keep` 保留容器供人工排查（默认关闭）
- 连跑 2 次结果一致（可重复）
